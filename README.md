# RPG Battle — консольная игра на Dart

Консольная RPG-игра, показывающая углублённое программирование в Dart: наследование, абстрактные классы, переопределение методов и полиморфизм. Два персонажа сражаются в пошаговой битве, пока один из них не победит

4. Запустить игру:

## Что изучили

- Наследование - создание классов-наследников через extends и вызов родительского конструктора через super(...)

- Абстрактные классы - abstract class Character как шаблон, который нельзя инстанцировать напрямую

- Абстрактные методы - attack() и toString() без реализации, обязательные к переопределению в наследниках

- Переопределение методов - @override, вызов super.method() для расширения поведения родителя (например, броня Воина)

- Полиморфизм - функция fight(Character attacker, Character defender) работает с любым наследником, вызывая его реализацию attack()

## Ответы на вопросы

1. **Что такое абстрактный класс? Почему нельзя написать Character() напрямую?**
Абстрактный класс — это шаблон. У него может не быть части методов, поэтому создать его напрямую нельзя. Можно создавать только наследников (Warrior, Mage, Archer), где все методы уже дописаны. Dart запрещает Character() на уровне компиляции

2. **Зачем нужен super в конструкторе наследника? Что будет, если его убрать?**
super() — это вызов конструктора родителя. Он нужен, чтобы родитель инициализировал свои поля (name, hp, maxHp)

3. **В чём разница между @override у attack() и takeDamage() в Warrior?**
attack() в Character — абстрактный (без тела). Warrior обязан его написать — иначе код не скомпилируется

    takeDamage() в Character — обычный, уже с готовым кодом. Warrior переопределяет его, чтобы добавить броню, а потом вызывает super

    @override в обоих случаях просто говорит компилятору: «проверь, что такой метод есть у родителя» — чтобы не было опечаток

4. **Функция fight(Character a, Character b) не знает, кто реально придёт. Как называется эта концепция и где вы её видели во Flutter?**
Переменная типа родителя (Character) может хранить любого наследника, а a.attack() вызовет свою версию метода — ту, что у реального класса

    Во Flutter то же самое: Widget build() возвращает Widget, но реально там может быть Text, Column, ElevatedButton — любой наследник. MyApp extends StatelessWidget и @override build() — ровно та же схема, что Warrior extends Character и @override attack()

5. **Что означает _random с нижним подчёркиванием в классе Character?**
Подчёркивание _ в начале имени делает поле приватным — доступным только внутри файла character.dart. Из других файлов (например, characters.dart) к _random обратиться нельзя. Это нужно, чтобы скрыть внутренние детали: наследникам не надо знать, как именно родитель генерирует случайные числа
